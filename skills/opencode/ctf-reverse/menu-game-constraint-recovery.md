# Reverse - Menu-driven game binaries as constraint systems

## Menu-game finale ladder as a constraint system

**Trigger:** An interactive "simulator" binary presents a numbered menu for a fixed number of turns, ends in a long run of `cmp` instructions against integer literals, and only then derives and prints something — often next to a visible near-miss flag string.

Read the finale `cmp` ladder as a system of equations over the game's state variables rather than playing the game. Recover each menu action's deltas from its handler (score/mood/energy/bond increments and the counter it bumps), then solve the ladder's equalities and inequalities for an exact action multiset; a score equality plus per-action count equalities usually pins the multiset uniquely, and turn count constrains the total. Any state word that is an order-dependent rolling hash or a small "rhythm" state machine constrains the *sequence*, not the counts — simulate candidate permutations of the already-fixed multiset against that hash instead of solving it algebraically. Treat quoted NPC/owner dialogue as literal specification: a last-day line naming a word is usually the exact string a text input is compared against, and finale error strings ("the words feel the wrong length", "a different sequence of tricks") each name which constraint you failed. Where a text input is only checked by a non-cryptographic hash and a length, solve the preimage under an alphabet constraint and use a second checksum over all inputs to disambiguate candidates. Once the state is pinned, the flag decryptor is typically seeded from the final stats via an avalanche mix, so you can produce the flag statically — and separately replay the recovered menu sequence interactively to confirm. Be suspicious of any plaintext flag-shaped string whose prefix differs by one character from the event's real prefix: that is a deliberate lure branch, and grep-for-flag-format tooling will surface it with equal confidence.
